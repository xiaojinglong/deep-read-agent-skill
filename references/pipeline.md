# 读书精读流水线详解

## 概述

读书精读智能体执行一条 7 步串行流水线，从选书到输出完整精读笔记。每一步都有明确的输入、输出和质量标准。

## 流水线步骤

### Step 0: 初始化

```
日期 = 当天日期 (YYYY-MM-DD)
时段 = HHMM（当前时分）
task_id = book_${日期}_${时段}
Python 解释器路径
```

确定项目根目录（即 book_list.json 所在目录）。

---

### Step 1: 选书

三种选书方式：

**方式 A — 按优先级自动选（默认）:**
```bash
python scripts/book_manager.py select
```
选书规则：
- 优先级：高 > 中 > 低
- 优先选择 `last_read` 为 null 的书
- 全部已读时，选 `last_read` 日期最早的

**方式 B — 指定书名:**
```bash
python scripts/book_manager.py select --title "书名关键词"
```

**方式 C — 随机选:**
```bash
python scripts/book_manager.py select --random
```

输出 JSON：`{ "selected": true, "title": "...", "author": "...", "priority": "...", "tags": [...], "en_slug": "..." }`

---

### Step 2: 写入书籍元数据

将选中书籍的元数据写入 `book_cache/book_meta/${task_id}.json`：

```json
{
  "task_id": "book_20260827_1030",
  "title": "书名",
  "author": "作者",
  "priority": "高",
  "tags": ["标签1", "标签2"],
  "en_slug": "pinyin-slug",
  "selected_at": "2026-08-27T10:30:00+08:00",
  "last_read_before": null
}
```

---

### Step 3: 生成深度精读内容（核心步骤）

这是整个流水线最核心、最耗时的步骤。目标是生成一份 **≥15000字** 的 HTML 精读笔记。

#### 3.1 生成 HTML 骨架

```bash
python scripts/html_template.py generate \
  --title "书名" \
  --author "作者" \
  --task-id ${task_id} \
  --tags "标签1,标签2" \
  --priority "高"
```

输出骨架文件到 `book_cache/book_raw_content/${task_id}.html`，包含完整的 CSS 样式和 15 个模块的占位结构（v5 版含 emoji 标题、场景步骤心法格式、一页精华复盘块）。

#### 3.2 填充内容

读取骨架文件，**分 2-3 次写入**完整内容（15000字内容量大，单次写入容易截断）。

**15 模块结构与字数目标（总约 13000 字）:**

| # | 模块 | Emoji | 字数 | 核心要求 |
|---|------|-------|------|----------|
| ① | 荣誉与口碑 | 🏆 | 150 | 豆瓣评分、名人荐读、机构推荐、平台数据、版本信息 |
| ② | 作者简介 | ✍️ | 600 | 身份+跨界身份（4维度）+写作动机（引用块） |
| ③ | 目标读者与阅读价值 | 👥 | 700 | 4类读者画像（reader-card）+5项收获+实际应用价值 |
| ④ | 创作背景 | 🌐 | 600 | 时代背景+故事原型+写作手法 |
| ⑤ | **核心理论逐章拆解** | 🔬 | **5000** | **最核心。每个工具含场景→步骤→心法，覆盖全书** |
| ⑥ | 实用案例 | 📌 | 800 | case-card格式，案例拆解+一句话启发 |
| ⑦ | 读者笔记精选 | 💭 | 1000 | 按主题分类，划线+批注双层呈现 |
| ⑧ | 关键数据与事实 | 📊 | 300 | 核心数据+架构解读 |
| ⑨ | 金句摘录 | 💎 | 500 | 按主题分组，blockquote+insight解读 |
| ⑩ | 作者底层逻辑 | 🧠 | 700 | 核心因果链+可迁移法则+隐含世界观 |
| ⑪ | 可视化图表总结 | 📈 | 700 | ≥4种CSS图表：条形图/时间线/思维导图/流程图/雷达图 |
| ⑫ | 落地实践指南 | 🎯 | 700 | ≥6条行动建议+分阶段路线图表格+复用场景 |
| ⑬ | 跨书关联 | 🔗 | 300 | 阅读地图+关联表格+阅读建议 |
| ⑭ | 客观评价 | ⚖️ | 600 | 评分+认同之处+存疑之处+最大认知增量 |
| ⑮ | 一页精华 | 📖 | 300 | recap格式：四段式复盘（核心价值+最大收获+规避误区+一句话总结） |

#### 3.3 内容深度要求

- 每个观点都要有"为什么"：不只是作者说了什么，还有他为什么这么说
- 案例要讲细节：人物、时间、冲突、转折、结果，像讲故事一样还原
- 数据要有解读：数字本身不说明问题，要说清它意味着什么
- 时刻回答"所以呢"（So what）：这部分内容对读者的人生有什么用
- 章节间要有联系：每章结尾说明它在全书中的位置

---

### Step 4: 质检

```bash
python scripts/qc_check.py book_cache/book_raw_content/${task_id}.html
```

质检项（全部通过才算 OK）：
- [ ] 字数 ≥ 15000（去 CSS/style/script/注释/head 后统计纯文字）
- [ ] 15个模块全部存在且有实质内容
- [ ] ≥ 4种有效图表
- [ ] 章节卡 ≥ 8
- [ ] 金句 blockquote ≥ 12
- [ ] 数据表行 ≥ 12
- [ ] 行动建议 ≥ 6
- [ ] 无占位符残留
- [ ] HTML 闭合
- [ ] 无重复注水

不达标 → 补充生成缺失部分（最多重试2次）。

---

### Step 5: 更新阅读状态

```bash
python scripts/book_manager.py update "书名"
```

更新 `book_list.json` 中该书的 `last_read` 为今天，`user_read` 设为 `true`。

---

### Step 6: 写日志

将运行日志写入 `book_cache/book_log/${task_id}.log`：

```
[2026-08-27 10:30:00] Task: book_20260827_1030
  Book: 《书名》
  Author: 作者
  Status: success
  Output: book_cache/book_raw_content/book_20260827_1030.html
  WordCount: 12800 (body text, CSS excluded)
  Modules: 15/15
  Chapters: 12/12
  Charts: 5
  DataRows: 12
  Quotes: 12
```

向用户展示格式化摘要：

详细说明（2-3行）

## 多本连读

用户可说"读3本""连读5本"：
1. 循环执行 Step 0-7，每次选不同的书
2. 每本生成独立 HTML 文件
3. 最后汇总展示

## 约束

- 失败不中断，记录错误到日志继续执行
- 精读内容基于 AI 对书籍的理解生成，不要求原文搬运
- 但章节结构、核心观点、关键数据必须忠于原书，不许虚构章节
- 每次精读只读一本书
- 输出文件名: `${task_id}.html`
