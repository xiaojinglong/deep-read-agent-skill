# Step 2.5 事实核验（联网检索）

> 这一步是为了解决精读笔记最大的质量风险：**模型把" plausible "当成"事实"写进去**。
> 章节名是编的、豆瓣评分是猜的、关键数据是估的 —— 这种笔记看着完整，实际是毒药。
> 在生成 15000 字之前，先花几分钟把可核验的事实钉死。

## 什么时候做

Step 2（写元数据）之后、Step 3（生成内容）之前，**强制**执行。

## 要核验什么

按优先级，逐项检索。**只核验可核验的事实，观点和评价留给 AI 自己写。**

### 必检项（缺一项就必须标注"未核实"）

| 项目 | 检索关键词模板 | 用途 |
|------|---------------|------|
| 豆瓣评分/评分人数 | `<书名> 豆瓣 评分` | 模块① 荣誉与口碑 |
| 出版信息 | `<书名> <作者> 出版社 版次 年份` | 模块①、④ |
| 作者真实身份 | `<作者> 身份 履历 代表作` | 模块② 作者简介 |
| **全书章节结构** | `<书名> 目录 章节 大纲` | **模块⑤ 逐章拆解，最关键** |
| 作者写作动机 | `<书名> 创作背景 为什么写这本书` | 模块④ 创作背景 |
| 书内核心数据 | `<书名> 数据 统计 研究发现` | 模块⑧ 关键数据 |

### 选检项

- 名人荐读 / 获奖情况 → 模块①
- 书中提到的其他书目 → 模块⑬ 跨书关联
- 豆瓣短评、微信读书划线 → 模块⑦ 读者笔记
- 争议批评意见 → 模块⑭ 客观评价

## 执行方式

用搜索工具至少跑完所有必检项。把结果整理成事实清单写入
`book_cache/book_meta/${task_id}_facts.md`：

```markdown
# 《书名》事实核验清单
核验时间: 2026-10-08
核验状态: 完整 / 部分（缺: XXX）

## 出版信息
- 首版: 2011年，中信出版社
- 豆瓣: 8.5（约 12.3 万人评价）   <- 来源: 豆瓣读书

## 章节结构（12章）
1. 第一章《XXX》
2. 第二章《YYY》
...

## 关键数据
- 数据来源某页：xxx%（说明 xxx）

## 未核实项
- 微信读书划线数：未查到，写作时不得杜撰
```

## 铁律

1. **章节结构必须来自检索**。没查到目录时，宁可按"全书论证脉络"组织，
   也**绝对不能编造章节标题**。这是模块⑤ 占 5000 字，编了就是整篇报废。
2. **数据必须带出处**。写"研究表明 70% 的人……"时，如果检索没给出这个数字，就不许写。
   改成不带数字的定性描述。
3. **评分未知就写"未核实"**，不猜。
4. **核不出来的项，在facts清单里显式列出**，Step 3 生成时必须绕开它们。

## 检索全部失败时

降级策略（不要中断流程）：

- 写 facts 文件，标注 `核验状态: 失败（网络不可用）`
- Step 3 生成时**禁止使用**任何具体数字、评分、获奖信息
- 改用定性表述："这本书在读者中口碑较高"（而非"豆瓣8.5分"）
- 模块⑤ 改为按主题维度组织，而非按章节 —— 并在文中说明
  "本书结构未线上核实，此处按论证脉络梳理"
- 在最终摘要里向用户说明：本次未联网核验，具体数据请以原书为准

## 为什么这步不能省

15000 字的笔记里，读者最容易记住的恰恰是那些具体的东西 ——
一个评分、一组数据、一个章节名。**这些东西错了，整篇笔记的可信度归零**，
而它们偏偏是模型最容易"顺手补全"的部分。
